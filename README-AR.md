# سوشيال ويب — حزمة GitHub Pages / PWA

ابدأ هنا. الموقع لا يحتاج npm أو build أو سيرفر Node. ارفع ملفات هذا المجلد كما هي.

## الرفع على GitHub Pages

1. افتح حساب GitHub الخاص بك وأنشئ مستودعًا عامًا، مثل `social-web`.
2. فك ZIP على جهازك. ارفع **محتويات** الحزمة بحيث يكون `index.html` في جذر المستودع، وليس داخل مجلد إضافي.
3. من Settings → Pages اختر Deploy from a branch ثم `main` و`/(root)` ثم Save.
4. انتظر ظهور رابط النشر. لحساب `ah1310` ومستودع `social-web` يكون عادةً:
   `https://ah1310.github.io/social-web/`
   هذا مثال للرابط المتوقع بعد رفعك؛ لم أنشئ المستودع أو أنشره في حسابك.
5. للحصول على `https://ah1310.github.io/` مباشرةً استخدم مستودعًا اسمه `ah1310.github.io`، مع الحفاظ على أي موقع حالي عندك.
6. اختبر الرابط عبر HTTPS. لا تفتح `index.html` بالنقر المزدوج لتجربة المكالمات أو PWA؛ `file://` لا يدعمهما.

كل مسارات التطبيق نسبية. يعمل في جذر github.io وفي مسار مستودع فرعي. ارفع `.nojekyll` ومجلدات `icons` و`vendor` وملف `sw.js` أيضًا. قد لا تظهر الملفات التي تبدأ بنقطة في بعض واجهات رفع الملفات؛ استخدم Git أو GitHub Desktop إن لزم للحفاظ على `.github` و`.nojekyll`.

## ماذا يعمل فور رفع الملفات؟

- اسم وأيقونة «سوشيال ويب»، واجهة عربية، قائمة جانبية، وضع نهاري وليلي.
- وضع ضيف باسم عرض محفوظ محليًا، ومحادثة مباشرة بين جهازين بكود ورابط دعوة، مع قبول أو رفض الطلب.
- رسائل نصية، مؤشر كتابة، تأكيد استلام، رسائل صوتية حتى دقيقة.
- إرسال ملفات في الاتجاهين حتى ٥٠ ميجابايت للملف. تنزيل الملفات قبل إغلاق الصفحة. حتى ٢٠ ملفًا في ذاكرة الجلسة.
- مكالمات صوت وفيديو بين جهازين، قبول/رفض، كتم الميكروفون، تشغيل/إغلاق الكاميرا وإنهاء المكالمة.
- مشاركة شاشة من المتصفحات التي تدعم `getDisplayMedia` وتسجيل البث المستلم أو المحلي على الجهاز حتى ١٠٠ ميجابايت. لا يتم دمج مسارين صوتيين تلقائيًا في التسجيل.
- دفتر جهات محلي: اسم، وظيفة، معرّف/ملاحظة، رابط؛ بحث واستيراد وتصدير JSON.
- حفظ الرسائل النصية محليًا اختياري، حتى ٢٠٠ رسالة، مغلق افتراضيًا.
- اختصارات للخدمات الأصلية: WhatsApp، Telegram، Messenger، Instagram، Facebook، YouTube، TikTok، X وLinkedIn. لا تُقرأ رسائل تلك الخدمات داخل الموقع.
- PWA بمانيفست وأيقونات PNG وmaskable وApple touch وService Worker. الواجهة تعمل دون إنترنت بعد أول زيارة ناجحة. الربط والمكالمات والرسائل السحابية تحتاج اتصالًا.
- **لا يوجد Chatbot**، وفق طلبك الأخير.

## اختبار جهازين

1. على الجهاز الأول افتح المحادثات → إنشاء جلسة جديدة.
2. أرسل الكود أو رابط الدعوة للجهاز الثاني.
3. على الجهاز الثاني أدخل الكود واضغط طلب التواصل.
4. وافق على الطلب من الجهاز الأول. أسماء الضيوف يكتبها أصحابها وليست هويات موثّقة.
5. جرّب رسالة وملفًا صغيرًا، ثم جرّب صوت وفيديو بعد السماح للمتصفح.
6. لاختبار دول أو شبكات مختلفة، استخدم شبكة هاتف على أحد الجهازين. إذا نجحت الرسائل ولم تنجح الوسائط، قد تحتاج TURN كما هو موضح أدناه.

في وضع الضيف تحتاج الصفحتان أن تظلا مفتوحتين. قفل شاشة الهاتف أو تقييد المتصفح في الخلفية قد يوقف الاتصال. لا توجد مكالمات واردة موثوقة والتطبيق مغلق ولا push notifications في هذه الحزمة.

## الحسابات السحابية — بيانات الاتصال مضبوطة وإعداد قاعدة البيانات مطلوب

تم إدراج Project URL والمفتاح العام اللذين زوّدتنا بهما في config.js. لم يتم التحقق من تنفيذ SQL أو إعدادات Auth في المشروع. وضع الضيف يعمل دون قاعدة البيانات؛ أكمل الخطوات التالية لتفعيل الحسابات والبحث والرسائل السحابية:

1. أنشئ مشروعًا جديدًا في Supabase. استخدم قاعدة مخصصة أو راجع الأسماء قبل تطبيق المخطط على مشروع موجود.
2. افتح SQL Editor وشغّل `supabase/schema.sql` **مرة واحدة**. الملف ينشئ الجداول والسياسات وtrigger لملف المستخدم. لا تشغله مجددًا على نفس المخطط بلا migration.
3. من إعدادات المشروع انسخ Project URL و**Publishable key أو anon public key**.
4. ضع القيمتين في `config.js` في `supabaseUrl` و`supabaseAnonKey`.
5. **ممنوع وضع service_role أو secret key أو كلمة مرور قاعدة البيانات في config.js أو GitHub.** ملفات الواجهة عامة.
6. في Authentication → URL Configuration اضبط Site URL على رابط موقعك النهائي، وأضف رابط المجلد نفسه في Redirect URLs، مع الشرطة المائلة الأخيرة. الاستعادة وتأكيد البريد يعودان لهذا الرابط.
7. استخدم Email/Password. لا تضف مزودي تسجيل دخول اجتماعي قبل إعدادهم؛ الحزمة تدعم البريد وكلمة المرور فقط.
8. أنشئ مستخدمين من واجهة إنشاء الحساب، كل واحد بمعرّف فريد من ٣ إلى ٢٤ حرفًا إنجليزيًا صغيرًا/رقمًا/شرطة سفلية. الوظيفة اختيارية ومرئية في البحث للمستخدمين المسجلين.
9. إذا كان تأكيد البريد مفعّلًا، افتح رسالة التأكيد ثم سجّل الدخول. للنشر العام، اضبط SMTP الخاص بك ومحددات الإرسال وCAPTCHA في Supabase وفق احتياجك.
10. ابحث بالاسم أو المعرّف أو الوظيفة؛ أرسل طلب تواصل. الطرف المستقبل يقبل أو يرفض. الطرفان المقبولان يستطيعان تبادل الرسائل النصية السحابية. القراءة تُحدّث كل ١٢ ثانية أثناء فتح الموقع، وليست إشعارات خلفية.

الرسائل النصية السحابية تبقى عند غياب الطرف الآخر. تسجيل الدخول يجعل الجهاز متاحًا لجلسات مباشرة وهو مفتوح. المكالمات والملفات تحتاج الطرف الآخر متصلًا وقبول الجلسة ثم المكالمة. الملفات لا تُرفع إلى Supabase.

المخطط يفعّل RLS: لا يقرأ الرسائل إلا مرسلها ومستلمها، ولا تُرسل رسالة سحابية إلا لجهة مقبولة. المستلم فقط يغيّر حالة الطلب. ملفات البحث تحتوي الاسم والمعرّف والوظيفة فقط؛ لا يُنشر البريد. راجع `supabase/VERIFY-RLS.sql` بعد الإعداد. لم يُختبر المخطط على مشروعك لعدم توفر مشروع أو مفاتيح في هذه الجلسة.

## Supabase ووضع النوم

يوجد ملف متابعة `.github/workflows/supabase-health.yml` يختبر جدول `health_check` العام يوميًا وعند التشغيل اليدوي. لتفعيله: أضف في Repository → Settings → Secrets and variables → Actions مفتاحين باسم `SUPABASE_URL` و`SUPABASE_ANON_KEY`، ثم فعّل Actions وشغّل workflow مرة.

هذا فحص توفر حقيقي ذو استعلام قاعدة بيانات، ولا يحتاج service_role. عدم ضبط القيم يجعل الفحص يتخطى نفسه بدل أن يفشل. إذا فشل فحصٌ مفعّل، راجع إشعار GitHub وSupabase Dashboard. لا يستعيد مشروعًا متوقفًا ولا يستطيع ضمان منع الإيقاف. جداول GitHub Actions نفسها غير مضمونة التشغيل في وقت محدد وقد تُعطل في مستودع غير نشط.

وفق سياسة Supabase، قد تتوقف المشاريع المجانية قليلة النشاط خلال ٧ أيام؛ **خطة Pro هي التي تضمن عدم الإيقاف بسبب قلة النشاط**. لا أقدّم health check كبديل مضمون عنها. استعد المشروع المتوقف من Dashboard ثم أعد الاختبار.

المصدر الرسمي: https://supabase.com/docs/guides/deployment/going-into-prod#availability

## مكالمات مصر والسعودية وأي بلد — TURN

البرنامج يستخدم WebRTC وPeerJS Cloud للإشارة، وSTUN لاكتشاف مسار الاتصال. لا توجد خدمة TURN مدفوعة أو بيانات اعتماد جاهزة في الحزمة. قد تنجح المكالمات مباشرة بين دول مختلفة، لكن بعض شبكات الجوال/الشركات أو NAT تمنعها.

لتحسين نجاح الاتصال، وفّر خدمة TURN موثوقة أو خادم coturn خاصًا بك، وضع إعدادها ضمن `iceServers` في `config.js`. يدعم WebRTC خوادم `turn:` و`turns:`؛ اتبع بيانات مزودك. لا تضع كلمة مرور TURN دائمة وحساسة في مستودع عام. للإنتاج استخدم endpoint خاصًا بك لإصدار بيانات TURN مؤقتة ومقيّدة، ثم حدّث إعداد PeerJS قبل إنشاء Peer. هذا endpoint غير مستضاف تلقائيًا مع GitHub Pages.

بديل تحكم أكبر: استضافة PeerServer الخاص بك بدل PeerJS Cloud. يحتاج خادمًا وإعداد TLS. PeerJS Cloud خدمة خارجية؛ لا أضمن توفرها أو رسومها مستقبلًا. المرجع: https://peerjs.com/docs/

## التثبيت على الهاتف

- آيفون: افتح في Safari → مشاركة → إضافة إلى الشاشة الرئيسية → إضافة.
- أندرويد: Chrome → قائمة ⋮ → تثبيت التطبيق/إضافة إلى الشاشة الرئيسية، أو زر التثبيت عند ظهوره.
- كمبيوتر: أيقونة تثبيت التطبيق في Chrome/Edge عند دعمها.
- بعد تحديث الموقع، افتحه أثناء الاتصال ثم أعد تحميله. عند تغيير ملفات الواجهة غيّر `VERSION` في `sw.js` حتى تتجدد نسخة الكاش. إعدادات الحساب لا تُخزّن في Service Worker؛ جلسة Supabase يستخدمها SDK في تخزين المتصفح.

## حدود يجب معرفتها

- الآيفون لا يرسل شاشته كاملة من Chrome/Safari في هذا الموقع. PWA لا يرفع هذا القيد؛ يمكنه استقبال بث أو استخدام الكاميرا والميكروفون عند دعم المتصفح.
- هذه حزمة تواصل بين جهازين، وليست شبكة اجتماعية كاملة بحجم واتساب. لا تشمل مجموعات متعددة الأطراف أو إدارة إساءة/حظر متكاملة أو إشعارات push أو بنية TURN جاهزة أو تطبيق متجر.
- رسائل Supabase النصية ليست تشفيرًا طرفًا لطرف. تتم عبر HTTPS وتتحكم RLS في الوصول؛ يمكن لمالك قاعدة البيانات إدارتها. اتصال WebRTC يستخدم تشفير النقل الخاص به.
- مسح بيانات المتصفح يمسح الاسم والجهات والسجل المحلي. صدّر الجهات للاحتفاظ بنسخة.
- لا يوجد دمج فعلي لصناديق رسائل منصات أخرى. روابطها تفتح الخدمة نفسها.
